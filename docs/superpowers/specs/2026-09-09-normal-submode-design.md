## 1. What Normal actually changes

Read against Ch. 45, most of the Normal rulebook is **already implemented**, because the Advanced
ruleset shares it. Contracts — 6 for an Unbound Servant, 5–6 for a Free one, the two-panel enemy
clearance, allied-automatic on Free and forbidden on Unbound, conquest on a Master kill and the
Command Spells that come with it — are `rules/contract.mjs`, clause for clause. ZON and its 5d10
damage reduction, the Master's +1 MOV while adjacent, the whole cover-and-redirect ladder and its
Presence Concealment exception are `rules/zon.mjs` and `rules/relationships.mjs`. Sustainability and
its Free-Servant clock, the day/night cycle and the `Dark` attribute's ±25%, home base E1–E5, the
Grail's contest and destruction odds, Civilians, the three-turn round: all built.

**Four things differ**, and nothing else:

1. Stats are generated by different dice.
2. Statblocks are flat numbers rather than parameter ranks.
3. Class skills are fixed dice rather than rank tables.
4. The difficulty levels switch named rules off.

That is the whole delta, and it is why this is a stat layer plus a content pack rather than a second
engine.

## 2. Setup rolls — a second plan, in the vocabulary that exists

> *"Roll for Health (S): 10d20 · Roll for Agility (S): 1d10+10 · Roll for Luck: 1d20 ·
> Roll for Health (M): 5d20 · Roll for Agility (M): 1d12"*
>
> *"For every Servant, Flip a Coin, then Roll for Health(S). If Heads, the Max Health is the Base
> Health plus the rolled value. If Tails, the Max Health is the Base Health minus the rolled
> value."*

New `module/rules/setup-rolls-normal.mjs`, Layer 2, pure, caller rolls. **No new line vocabulary is
needed.** `signCoin`, `map`, `derivedFrom`, `base` and `roll.formula` all exist already, because the
Advanced Master's Max Health is itself a coin-signed `2d100` and the coin-flip rank line already maps
`1d2` onto letters.

```
normalServantSetupPlan(sheet)
  maxHealth   base = sheet.baseHealth      roll { formula: "10d20", signCoin: true }
  maxAgility  base = 10 + agilityDelta     roll { formula: "1d10" }
  maxLuck     base = luckDelta             roll { formula: "1d20" }

normalMasterSetupPlan(sheet, { mode })
  maxHealth   base = 250                   roll { formula: "5d20", signCoin: true }
  maxAgility  base = 0                     roll { formula: "1d12" }
  maxLuck     base = 0                     roll { formula: "1d20" }
  rank        (mode === "coinFlip")        roll { formula: "1d2", map: ["A", "C"] }
  baseAttackMag  derivedFrom "rank" → { A: 125, B: 125, C: 100, D: 100 }, fallback 100
  commandSpells  base = 3                  no roll
```

The class deltas — *"Lancer +2, Rider +1, Caster −2, Assassin +3"* for Agility and *"Lancer −2,
Assassin +2"* for Luck — go into `domain/tables.mjs` as `normalAgilityByClass` and
`normalLuckByClass`, looked up through `lookup()` the way every other class and rank table already
is, rather than as constants in the plan module.

`setup-rolls.mjs` gains a `plansFor(ruleset)` dispatcher so there is one import site, and
**`needsSetupRolls` becomes ruleset-aware**. Today it keys on *"a parameter rank is stated and the
stat is unrolled"*, which is exactly right for Advanced and silently false for Normal, where no
Servant states a rank — so `ensureSetupRolls` would never flag a Normal Servant with a zero maximum,
and a zero Agility maximum auto-fails every Evade.

**The optional High/Low Rank coin needs nothing new.** *"Flipping a Coin for each Master;
Heads=High Rank, Tails=Low Rank … High Rank Masters: Base Attack (MAG)=125, ZON+1 panel, Servant's
Sustainability +1◈ Turns"* is `masterMode: "coinFlip"` and `rules/master-rank.mjs`, which already
grants all three.

## 3. Two defects this exposes

### 3.1 `MasterData` has no `baseAttack`, so every Master attacks for zero

`engine/summon.mjs:369` maps the rolled line to `system.baseAttack.mag`. `MasterData` declares no
such field — it borrows only `turnState` and `roundState` from `combatantCommon()`, and
`unitCommon()` has no Base Attack either. Foundry drops the unknown path without complaint, and
`rules/snapshot.mjs:190` reads `sys.baseAttack?.str ?? 0`.

Measured live in `fgt2026`, on all three Masters in the world:

```
MasterData schema fields: … rank, commandSpells, commandSpellsPerServant, zon, essences, servantIds
                          ↑ no baseAttack
Our Master → system.baseAttack: null
unitSnapshot("Our Master") → { kind: "master", baseAttack: { str: 0, mag: 0 }, mov: 0, range: 1, zon: 2 }
```

This is an **Advanced** defect. It is unfindable there only because nothing in the Advanced corpus
depends on a Master's own attack being non-zero; Normal states one on every Master sheet and gives
each of them a Magic Crest, so it becomes load-bearing.

The fix takes the definition from the one place it already exists rather than writing a second one,
the way `turnState` and `roundState` are already taken:

```js
// module/data/actor/master.mjs
const { turnState, roundState, baseAttack } = combatantCommon();
```

Master content then supplies `mov: 2` and `range: {panels: 2, targets: 1}` — `unitCommon` fields
sitting at their 0 and 1 defaults today for want of any Master content at all (§4).

### 3.2 A stated ZON swallows High Rank's +1

`zonRadius` ends:

```js
const derived = radius + exclusive + stacking + rankBonus;
return Math.max(derived, master?.zon ?? 0);
```

The floor exists so *"a Master sheet that states a number is stating it"*, and `rankBonus` sits
inside `derived` deliberately — the comment argues that a stated ZON should not swallow a rank
bonus. It does exactly that whenever the stated number is the larger one, which in Normal is
**every Master**: the sheets state ZON 2 for Saber, Lancer, Rider and Berserker, 4 for Archer and
Assassin, and 5 for Caster. A High Rank Normal Archer's Master computes `derived = 2 + 0 + 0 + 1 =
3`, then `max(3, 4) = 4`, and the +1 the rank bought is gone.

```js
return Math.max(derived, (master?.zon ?? 0) + rankBonus);
```

The floor is about the class-derived half; a rank grant is a different thing and belongs on both
sides of the comparison.

## 4. Content

### 4.1 A pack per ruleset

`packs/_source/servants-normal/` with a `PACKS` entry mapping it to a new `fgt.servants-normal`
compendium, declared in `system.json`. A separate pack rather than a prefix inside `servants`,
because the wizard's catalogue must filter by ruleset and a pack boundary is a filter that cannot be
got wrong by an id typo.

### 4.2 Masters exist at last

`packs/_source/masters/` does not exist. The `masters` pack is declared in `system.json`, mapped in
`PACKS`, backed by a full `MasterData` schema, and ships as an empty LevelDB directory. This design
creates the directory with `master-advanced.yml` and `master-normal.yml`.

Per-class ZON is written onto `system.zon` at commit from the container's class, which needs **no
rule change**: the stored value is already read as a floor by `zonRadius` (and, after §3.2, a floor
the rank bonus is added to).

### 4.3 The seven Servants, and their skills

One generic set, named at commit as `Saber of <Faction>` and `Master of Saber of <Faction>` — the
source sheets differ across factions only in that word.

| Statblock | Base HP | MOV | Range | BA STR | BA MAG | Sus. | NP |
|---|---|---|---|---|---|---|---|
| Saber | 1250 | 4 | 1 / 1 | 200 | 150 | 2◈ | 1 |
| Lancer | 1000 | 5 | 2 / 1 | 125 | 125 | 2◈ | (a) 1, (b) 1 |
| Archer | 750 | 4 | 4 / 1 | 100 | 125 | 5◈ | (a) 2, (b) 1 |
| Rider | 1000 | 8 | 1 / 1 | 100 | 150 | 2◈ | 1 |
| Caster | 750 | 5 | 3 / 1 | 50 | 150 | 4◈ | (a) 2, (b) 1 |
| Assassin | 500 | 6 | 2 / 1 | 50 | 100 | 1◈ | — |
| Berserker | 750 | 3 [+2] | 2 [+1] / 1 | 100 | 125 | varies | (a) 2, (b) 1 |

Blank parameter ranks throughout, which is what makes these compile correctly with no schema change:
`domain/base-attack.mjs#baseAttackFor` keeps the authored figure where there is no rank to derive
from — *"the authored figure survives only where there is no parameter to derive from"* — and
`ServantData#prepareBaseData` fills `health.max` from `baseHealth` when no END rank is stated.

Class skills are authored as fixed-dice variants under `normal-` ids, and **the dice mode they all
need is already built**. `mode: "dice"` is a first-class shape on both the `Resistance` and
`DamageNegation` rule elements: `elements.mjs:750` projects it, `attack.mjs:2926` doubles the formula
when the incoming attack is a Noble Phantasm (`isNP && npDiceDoubled ? doubleDice(n.formula)`),
`pipeline.mjs:527-529` subtracts the rolled total and labels it *"never negates"*, `preview.mjs`
bounds it, and `test/unit/elements.test.mjs:79` and `:286` already cover both elements in that mode.
Every *"reduced by Nd20; if NP, double the number of dice rolled"* line on the Normal sheets is
therefore authored data and **no engine work at all**.

| Skill | Normal form | Rides on |
|---|---|---|
| Magic Resistance | `5d20` off MAG damage, doubled against NP | `Resistance` passive rule, `mode: "dice"`, `formula: "5d20"` |
| Battle Continuation | `2d20` off all damage, doubled against NP; one-shot `5d20` revival at 0 | `DamageNegation` in `mode: "dice"` with a fixed formula rather than a rank table, plus `RevivalSource` |
| Independent Action | coin for +3◈ Sustainability on Master death; contract roll performed twice | `rollsRequired` already returns 2 by default |
| Riding | Double Move, Riding Attack, Passenger Seat | `engine/riding.mjs` |
| Territory Creation | `5d20` damage boost in own base; `(3d10+20)` reduction for allies in it, lost if Caster dies | `rules/environment.mjs` E5 |
| Presence Concealment | untargetable; Hidden Strike, Assassination, Sneak Attack | `engine/concealment.mjs` |
| Mad Enhancement | Berserk Rage's five clauses; Master loses 15 HP per acting Turn; Sustainability 2◈ ↔ 1◈ | `rules/modes.mjs`, `engine/modes.mjs` |

Eleven Noble Phantasms and the Master's Magic Crest complete the set. **The "select NP (a) or (b)
before play" choice** for Archer, Caster and Berserker is the wizard's `npChoice`, committed by
marking the unselected Noble Phantasm `expended` — the sheet's own words are *"the unselected Noble
Phantasm is unusable"*, and `expended` is the existing way to say that.

Noted while checking the above, and deliberately **not** fixed here: the second, older route to the
same rule — the `ServantData.classSkills.magicResistance` schema field — has `snapshot.mjs:1428`
reading `mr.npDiceDoubled` and `mr.percent`, and the schema declares neither, so both are permanently
`undefined`. It is inert rather than wrong (`npDiceDoubled ?? true` is the answer Normal wants
anyway), no Servant authors that field, and the rule-element route above is the one the corpus and
the tests use. Recorded so the next reader does not take the field for a working control.

## 5. Difficulty

With the vocabulary unified by the war-setup spec, wire what each level removes:

| Level | Removes |
|---|---|
| Beginner | the ±5d10 damage-modifier roll **and** the Luck Check |
| Intermediate | the Luck Check |
| Expert | nothing |
| Lunatic | nothing; raises the Random Event rate |

> *"To play without damage modifiers, just use Base Attack for damage calculation instead of
> Attack+/Attack-."*

Both gates read `board.difficulty`, which `engine/board.mjs` already projects from the match. Lunatic
has exactly one mechanical clause — *"there should always be at least 2 Civilians on the board"* —
and `civiliansNeeded` already implements it, against a difficulty value nothing could previously set.

## 6. One refusal

A Normal war will not draw an Advanced Servant, or the reverse. The wizard's catalogue is filtered by
`MatchData.ruleset` and `commitSummon` re-checks, because a stale draft is the case a filter alone
does not cover. Stated explicitly because a mixed board is not a house rule a table might want — it
is two different stat scales in the same fight, where a Normal Saber's 1250 Health meets an Advanced
Servant's rank-derived 1600 and neither number means what the other means.

## 7. Testing

**Pure units.** `test/unit/setup-rolls-normal.test.mjs` — every class delta on both Agility and Luck,
both faces of the Health coin on a Servant and on a Master, the rank coin feeding Base Attack (MAG),
and `needsSetupRolls` flagging a rankless Normal Servant with a zero maximum (the case it silently
passes today). `test/unit/zon.test.mjs` gains the stated-ZON-plus-rank-bonus case for §3.2.
Difficulty gates get a table test: which of the two rolls survives at each of the four levels.

**Content.** `npm run validate:content` over the new packs, then `npm run build:packs`, which needs
the world shut down first — the application holds the LevelDB open even after the world is closed in
the browser, so `node tools/fgt-rebuild.mjs` is the command, not a bare build.

**Live, in `fgt2026`.** A two-faction Normal Great Holy Grail War built through the wizard, and on
screen: a Normal Berserker whose Max Health is `750 ± 10d20` with the coin's sign shown in the
workings; its Master with a Base Attack that is **not** zero, which is the §3.1 fix observed rather
than asserted; a High Rank Archer's Master reading ZON 5; and an Archer whose unselected Noble
Phantasm is present on the sheet and refuses to fire.

## 8. What this does not do

- **Advanced content is not touched.** The two rulesets share every engine module and no Advanced
  Servant changes.
- **The 3-player-per-faction variant** the rulebook opens with — *"Each Player controls seven
  Servants and seven Masters"* versus *"Each Faction has 7 players"* — is a seating arrangement, not
  a rule delta. The war-setup spec's `userIds[]` covers both and nothing here needs to know which.
- **Beginner and Intermediate remove two rolls and no more.** Neither level changes damage
  ordering, the pipeline, or any clause that names a die other than those two.
