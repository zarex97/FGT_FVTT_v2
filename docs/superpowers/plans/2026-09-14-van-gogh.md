# Van Gogh Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Van Gogh plays exactly as `char_orig_sheets/Copia de Van Gogh.md` reads, proven clause by clause on a live board through the interface.

**Architecture:** Her whole kit is one feedback loop — *curse yourself, and the Noble Phantasm comes back sooner.* The loop runs on a single new event, `curseStageChanged`, raised at the one place a stage is decided, so no Servant-specific code enters the write path. Every task pairs **one engine addition with the clause that consumes it**, so nothing lands inert. Engine work obeys the layer rule — `domain` (1) ← `rules` (2) ← `engine` (3) ← `apps`/`documents` (4), enforced by `tools/check-layers.mjs`.

**Tech Stack:** Foundry VTT v14 system, vanilla ESM (no build step for `module/`), vitest, YAML content packs, `claude-in-chrome` for live verification.

**Spec:** `docs/superpowers/specs/2026-09-14-van-gogh-design.md`

## Global Constraints

- **Three authorities for rule-element keys must agree.** A new key goes in `module/rules/elements.mjs` (`EXECUTORS`), `module/rules/authoring/elements.mjs`, and `tools/lib/content.mjs` (`RULE_ELEMENT_KEYS`). `test/unit/elements.test.mjs` holds them against each other in both directions.
- **Six authorities for a new actor/platform field.** Schema, `rules/snapshot.mjs` (which projects field by field), `actorSystem()` in `tools/lib/content.mjs`, `AUTHORED_ACTOR_KEYS` in `module/content/authored-fields.mjs`, and — for a new predicate — `module/rules/facets.mjs` plus `lang/en.json`. Four of the six are caught only by build checks.
- **Layer rule.** `module/rules/**` must not import from `module/engine/**` or reference Foundry globals (`game`, `ui`, `canvas`). Verified by `npm run lint`.
- **Predicate grammar.** `and`/`or`/`nand`/`nor` take statement objects; `anyOf` takes **bare option strings only**.
- **Every new roll option must be emittable.** Add its facet to `module/rules/facets.mjs` or `isEmittableOption` rejects it and `validate:content` fails. A new facet also needs `FGT.Predicate.Facet.<id>` and `…Hint` in `lang/en.json`, and the hint text must match the facet's `english` **exactly**.
- **`ApplicationChance.direction` is `incoming` / `outgoing`.** Not `inflicting`/`receiving` — that is what the authoring vocabulary currently *says*, and Task 3 fixes it. The executor defaults to `incoming`, so a wrong value applies silently in the wrong direction.
- **A resistance is a POSITIVE value inward.** `direction: incoming, value: 35` means "35 points harder to land on me". The applier subtracts it.
- **Chances above 100% are not clamped during accumulation** (spec R8). Only the final figure is clamped.
- **Effect ids must not collide with ability ids.** Her buff is `gogh`; her Servant id is `van-gogh`.
- **Gate before every commit:** `npm test && npm run lint && npm run validate:content && npm run check:manifest`.
- **World tooling:** `node tools/fgt-world.mjs status|launch|app:start|app:stop`, `node tools/build-packs.mjs` (**Foundry must be fully closed** — the app holds the LevelDB). If `launch` reports `noTile`, open `http://localhost:30000/setup` in the CDP browser first, then launch.

## Task 3: Item Construction — and a vocabulary that offers the wrong direction

**Files:**
- Create: `packs/_source/class-skills/item-construction-gogh.yml`
- Modify: `module/rules/authoring/elements.mjs`
- Modify: `test/unit/van-gogh.test.mjs`, `test/unit/elements.test.mjs`

**Interfaces:**
- Consumes: `Aura` with `group` and `stacking: highestOnly` (`rules/auras.mjs#resolveStacking`).
- Produces: the content id `class-item-construction-gogh`.

**The non-stacking clause is free** (spec R10). `rules/auras.mjs` resolves `highestOnly`, makes it the **default**, and its comment at line 254 quotes this very clause: *"Only the Item Construction with the highest Rank takes effect"*. `group: itemConstruction` makes the whole Skill win as a unit rather than blending two ranks tier by tier.

**The defect this task also closes.** `ApplicationChance.direction` is read as `incoming` / `outgoing` — `effect-applier.mjs` passes exactly those two strings and defaults to `incoming`. The authoring vocabulary offers `["inflicting", "receiving"]`, so a GM picking from the editor authors a value nothing matches and the clause silently applies **inward**. Same class as `orientedRect`'s `needs`, and Van Gogh is this element's second author.

```js
/**
 * Does this handler care about the event that just fired?
 *
 * `targetPredicate` asks about a UNIT; this asks about the EVENT. Channel
 * Marker Soul is the clause that needs the difference: *"inflicted with Curse
 * **or has Curse removed from herself to the effects of the 'Gogh' buff**"* is
 * one event, two directions, and only one of the directions is gated on a
 * source.
 *
 * Two forms, both narrow on purpose — a general expression language here would
 * be a second predicate grammar with none of the first one's tooling:
 *   `{ cause: "gogh" }`            — the event names this cause
 *   `{ stageDelta: "negative" }`   — a numeric field's sign
 * and `anyOf: [...]` to disjoin them.
 *
 * A filter naming a field the event does not carry REFUSES, which is the safe
 * direction: a handler that cannot tell what happened should not fire.
 *
 * @param {object|null} filter
 * @param {object} event
 * @returns {boolean}
 */
function eventFilterPasses(filter, event) {
  if (!filter) return true;
  if (filter.anyOf) return filter.anyOf.some((f) => eventFilterPasses(f, event));

  for (const [field, want] of Object.entries(filter)) {
    const got = event?.[field];
    if (want === "positive") { if (!(got > 0)) return false; continue; }
    if (want === "negative") { if (!(got < 0)) return false; continue; }
    if (got !== want) return false;
  }
  return true;
}
```

and in `fireEvent`, beside the existing `targetPredicate` gate:


- [ ] **Step 5: Let an action read the event payload**

```js
/**
 * An action magnitude that names a field of the event that fired it.
 *
 * `"-@stageDelta"` is Channel Marker Soul: *"reduce her NP Cooldown by 1 Turn
 * for every Stage of Curse inflicted/removed."* The number is not on the
 * ability and not on the unit — it is the size of the change that just
 * happened, and only the event knows it.
 *
 * A reference to a field the event does not carry yields `null`, and the
 * caller drops the action rather than treating it as zero: "the event had no
 * stage delta" and "the stage moved by nothing" are different, and only one of
 * them should be silent.
 *
 * @param {string|number|undefined} raw
 * @param {object} event
 * @returns {number|null}
 */
function eventValue(raw, event) {
  if (typeof raw === "number") return raw;
  if (typeof raw !== "string" || !raw.includes("@")) return null;
  const negate = raw.trim().startsWith("-");
  const field = raw.replace(/^-/, "").replace("@", "").trim();
  const value = event?.[field];
  if (typeof value !== "number") return null;
  return negate ? -value : value;
}
```

```js
/**
 * Strip a named effect from an area and re-apply what was taken to one Unit.
 *
 * > *"Remove all Curse debuffs from **all** Units within a 3 panel area of
 * > Gogh, then apply them to herself (apply all stages of Curse accordingly,
 * > if any affected Unit has more than one stage of Curse)."*
 *
 * Composed of intents that already exist — one `removeEffect` per source
 * instance and **one** `applyEffect` carrying the summed stages — so
 * `curseStageChanged` fires once per victim on the way out and once on the
 * recipient on the way in, and Channel Marker Soul is paid for both without
 * this function knowing it exists.
 *
 * `stageMode: "sum"` is stated by the caller rather than assumed: "the highest
 * stage moves" is a real alternative reading, and the sheet's parenthesis
 * settles it the other way.
 *
 * **It takes from enemies too.** The sheet bolds *all*, and the trade is the
 * point: she cleanses her opponents to fuel herself.
 *
 * @param {object} phase the `transferEffects` phase
 * @param {object} actor the caster
 * @param {object} board
 * @returns {Promise<Intent[]>}
 */
async function transferEffects(phase, actor, board) {
  const self = board.units.find((u) => u.id === actor.id);
  if (!self?.panel) return [];

  const area = expand(phase.from.shape, { panel: self.panel }, { bounds: board.bounds }).panels;
  const keys = new Set(area.map((p) => `${p.i},${p.j}`));
  const wanted = new Set(phase.from.relations ?? ["ally", "enemy", "self"]);

  /** @type {Intent[]} */
  const out = [];
  let stages = 0;

  for (const unit of board.units) {
    if (!unit.panel || !keys.has(`${unit.panel.i},${unit.panel.j}`)) continue;
    if (unit.id === actor.id && !wanted.has("self")) continue;
    if (unit.id !== actor.id && !wanted.has(relationOf(self, unit, board))) continue;

    for (const e of unit.effects ?? []) {
      if (e.defId !== phase.defId) continue;
      stages += phase.stageMode === "sum" ? (e.stage ?? 1) : 1;
      out.push(I.removeEffect(unit.id, e.id, "transferred"));
    }
  }

  // ONE application carrying every stage, not one per stage: the recipient's
  // own stage arithmetic is what `resolveStacking` is for, and N intents would
  // also raise N events where the sheet describes one transfer.
  if (stages > 0) {
    const to = phase.to === "self" ? actor.id : phase.to;
    out.push(I.applyEffect(to, {
      defId: phase.defId, stages, expiry: null, sourceUnitId: actor.id, cause: "transfer",
    }, actor.id));
  }
  return out;
}
```

```yaml
# is both simpler than checking and the only version that cannot drift from
# what really happened.

# spec R2 gates the removal half of that Skill to this buff specifically, so a
# Cure stripping her Curse pays nothing.

  Whenever Gogh performs a successful Attack, remove one stage of @effect[curse]{Curse} from her
  and apply @effect[atkUp]{Atk Up} for 1◈ Turns if a stage was removed. On a Crit, remove two
```

## Notes for the implementer

**The double payment is intended.** Imaginary Numbers Arts pays twice from one press — 3 Turns
from Channel Marker Soul as the stages land, and 1◈ from its own clause for the stages held. Spec
R1. Anyone reading the cooldown drop without the ruling will read it as double-counting and
"fix" it.

**Clamping a chance is the instinct, and it is wrong.** A 500% chance is not 100% — it is a number
meant to survive subtraction. Her own Item Construction reduces her incoming debuff chance by 35%,
and the excess is exactly what gets through. Clamp during accumulation and the clause silently
disappears.

**Three mechanisms mean "does not die" and they are not interchangeable.** Guts revives after
defeat; Invuln stops the damage; `DamageFloor` caps one source. Sunflower's Curse is the third,
and authoring it as either of the others makes her unkillable rather than merely Curse-proof.

**Two of her abilities are called `Het Gele Huis`.** One is a Skill at 5×5, one a Noble Phantasm
at 7×7, and they block each other. A `blockedBy` pointing at itself makes an ability permanently
usable or permanently dead, and both read plausibly from the sheet.

**`ApplicationChance.direction` is `incoming`/`outgoing`.** The authoring vocabulary said otherwise
until Task 3; the executor defaults to `incoming`, so a wrong value applies silently in the wrong
direction.

**`StatDelta`'s `add` is the attribute-tag list, not a number.** A number there was iterated as a
set and threw out of `contributionsOf`, taking the whole board snapshot with it — the defect
Drake's `uncharted` found. Sunflower's Curse uses `add: [immuneToKillYourself]`.

**`validate:content` is red from Task 1 to Task 11.** Eleven refs arrive over ten tasks. Do not add
stubs to silence it; Task 11 Step 4 is where it goes green — and where `alter-ego.yml`'s
long-standing *"declared, inert"* warning finally clears.

**Three fields this plan ADDS rather than assumes.** `eventFilter` on `OnEvent` (Task 5),
`npMagnitudeFactor` on an effect spec (Task 8) and `DamageFloor` (Task 7) do not exist yet. Each
needs its three key authorities to agree and a test that holds them against each other; do not
author content against any of them before its task has landed.

**The layer rule.** `module/rules/**` may not import from `module/engine/**` or touch
`game`/`ui`/`canvas`. Tasks 5, 7 and 10 all add code across the boundary; keep the pure decisions
in `rules` and the writes in `engine`.
