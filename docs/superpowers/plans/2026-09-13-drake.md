# Francis Drake Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Francis Drake plays exactly as `char_orig_sheets/Copia de Francis Drake.md` reads, proven clause by clause on a live board through the interface.

**Architecture:** Approach A — every novelty of the Golden Hind becomes **authored platform vocabulary** (five optional schema blocks) rather than a `module/engine/drake.mjs`. Each block is optional and defaults to today's behaviour, so the Hanging Gardens, the Storm Border and the Quetzalcoatlus are untouched. Every task pairs **one engine addition with the clause that consumes it**, so nothing lands inert. Engine work obeys the layer rule — `domain` (1) ← `rules` (2) ← `engine` (3) ← `apps`/`documents` (4), enforced by `tools/check-layers.mjs`.

**Tech Stack:** Foundry VTT v14 system, vanilla ESM (no build step for `module/`), vitest, YAML content packs, `claude-in-chrome` for live verification.

**Spec:** `docs/superpowers/specs/2026-09-13-drake-design.md`

## Global Constraints

- **Three authorities for rule-element keys must agree.** A new key goes in `module/rules/elements.mjs` (`EXECUTORS`), `module/rules/authoring/elements.mjs`, and `tools/lib/content.mjs` (`RULE_ELEMENT_KEYS`). `test/unit/elements.test.mjs` holds them against each other in both directions. **Drake adds no rule-element keys** — `ResourceDelta` and `CooldownDelta` are OnEvent *actions* in `module/engine/scheduler.mjs`'s action table, which is a different registry.
- **Layer rule.** `module/rules/**` must not import from `module/engine/**` or reference Foundry globals (`game`, `ui`, `canvas`). Verified by `npm run lint`.
- **Predicate grammar.** `and`/`or`/`nand`/`nor` take statement objects; `anyOf` takes **bare option strings only**. Enforced by `anyOfHoldsOnlyOptions` in `tools/lib/content.mjs`.
- **Every new roll option must be emittable.** Add its facet to `module/rules/facets.mjs` or `isEmittableOption` rejects it and `validate:content` fails.
- **`orientedRect` takes `short`/`long`, never `w`/`h`.** `module/rules/targeting/shapes.mjs:132` reads `shape.short` and `shape.long`. Task 12 fixes the vocabulary entry that says otherwise.
- **Cooldowns have two readers with OPPOSITE conventions.** An ability *phase* (`kind: cooldown`) goes through `skill-use.mjs#cooldownChanges`, where a `ticks` change **must** state `direction: down` or it counts *up*. An *OnEvent action* (`{key: CooldownDelta}`) goes through `scheduler.mjs`'s action table, which negates `ticks` itself and takes a signed `delta`. Drake uses both. Do not copy one shape into the other.
- **Resource paths differ by reader too.** A `kind: resource` phase takes a full path (`resources.galleonTokens.value`); a `ResourceDelta` action takes the bare name (`galleonTokens`).
- **A platform's content id is the `platform-` prefixed one.** `golden-hind.yml` declares `id: platform-golden-hind`, and `self:onPlatform:` takes that id, not `golden-hind`.
- **Effect ids must not collide with Servant ids.** Drake's id is `drake`; her effects are `uncharted` and `ignoreDef`.
- **Galleon Tokens are a resource, not an effect.** `resources.galleonTokens`, reached by `ResourceDelta`.
- **Gate before every commit:** `npm test && npm run lint && npm run validate:content && npm run check:manifest`.
- **World tooling:** `node tools/fgt-world.mjs status|launch|up`, `node tools/fgt-rebuild.mjs` (**Foundry must be fully closed** — the app holds the LevelDB, shutting the world down is not enough), `node tools/fgt-reload.mjs`.

## Task 2: Riding B — and a MOV Up that was hard-coded to Medusa's rank

**Files:**
- Create: `packs/_source/class-skills/riding-drake.yml`
- Modify: `packs/_source/effects/riding-active.yml`
- Modify: `packs/_source/class-skills/riding-medusa.yml`
- Modify: `test/unit/drake.test.mjs`

**Interfaces:**
- Consumes: the `ridingActive` effect id, and `GRANTS.doubleMove` / `ridingAttack` / `passengerSeat` from `module/rules/granted.mjs`.
- Produces: the content id `class-riding-drake`, referenced by `drake.yml`.

**The defect this task closes.** `riding-active.yml` carries `MovDelta value: 5` as a literal, with a comment explaining why it cannot read the `ridingMov` table: *"an effect is collected with `rank: null`, so a table lookup here has no grade to read."* That reasoning is correct, but the literal is **Medusa's** rank. Drake's Riding is **B**, and `ridingMov` at B is **4**. Reusing the effect unchanged would give her Medusa's +5 and the bug would be invisible — a MOV that is one too high looks like a MOV.

The fix is the shape `np-regen.yml` already uses: `value: "@magnitude"`, with each Riding variant passing its own number. Medusa's behaviour is unchanged and a test holds it.

```js
describe("Drake — Riding B (spec R2)", () => {
  const drake = src("class-skills", "riding-drake.yml");
  const medusa = src("class-skills", "riding-medusa.yml");
  const active = src("effects", "riding-active.yml");
  const grantsOf = (skill) =>
    skill.passiveRules.filter((r) => r.key === "GrantedAbility");

  it("gates ALL THREE grants on the Active, where Medusa gates only two", () => {
    // Her Active names "'Double Move', 'Riding Attack', and 'Passenger Seat'";

    // is the whole reason a Medusa variant exists, so it is honoured both ways.

    expect(rules[0].abilities).toEqual(["doubleMove", "ridingAttack", "passengerSeat"]);
    expect(rules[0].predicate).toEqual(["self:effect:ridingActive"]);
  });

  it("grants nothing at all without the Active — the negative is the ruling", () => {
    // If any GrantedAbility rule on Drake's Riding lacks the predicate, one of
    // the three is permanent and R2 is not implemented.
    for (const rule of grantsOf(drake)) {
      expect(rule.predicate).toContain("self:effect:ridingActive");
    }

  it("leaves Medusa's Double Move unconditional", () => {

    expect(unconditional).toHaveLength(1);
    expect(unconditional[0].abilities).toEqual(["doubleMove"]);

    expect(magnitudeOf(medusa)).toBe(lookup("ridingMov", Rank.parse("A")));
  });

  it("reads its cooldown off the table the sheet agrees with", () => {
    expect(lookup("ridingCooldown", Rank.parse("B"))).toBe("2◈");
  });
});
```

## Task 3: Galleon Tokens — the resource, the decay, and a chance the action table never had

**Files:**
- Modify: `module/engine/scheduler.mjs`
- Modify: `packs/_source/servants/drake.yml`
- Modify: `test/unit/drake.test.mjs`
- Modify: `test/unit/scheduler.test.mjs`

**Interfaces:**
- Consumes: `dispatch` from `module/engine/scheduler.mjs`; `ResourceDelta` and `CooldownDelta` from its action table.
- Produces: a `chance` field honoured by **every** OnEvent action, consumed by Task 4's Crit passive.

**The engine addition.** Effect *riders* already honour `a.chance` (`scheduler.mjs:686` — *"Riders state their own chance"*), but the action table does not. Drake's *"15% chance of gaining 1 Galleon Token"* is an **action**, not a rider, so it has nowhere to put the number.

Added to `dispatch` rather than to `ResourceDelta`, so it covers every action. Like terrain's `chance` clause (`scheduler.mjs:1486`), the sequence is pure — the roll arrives in `ctx.rolls` and a missing roll **logs itself by name** rather than firing or silently vanishing.

- [ ] **Step 1: Write the failing test**

Append to `test/unit/scheduler.test.mjs`, inside the existing `describe("ResourceDelta")` or beside it:

```js
describe("OnEvent actions — chance", () => {
  const action = { kind: "ResourceDelta", resource: "galleonTokens", delta: 1, chance: 15 };

  it("fires when the roll is at or under the stated chance", () => {
    const ctx = { ...baseCtx, rolls: { "action:ResourceDelta:galleonTokens": 15 } };
    const out = dispatch(action, drake(), handler, ctx);
    expect(out).toHaveLength(1);
    expect(out[0].delta).toBe(1);
  });

  it("does not fire when the roll is over it", () => {
    const ctx = { ...baseCtx, rolls: { "action:ResourceDelta:galleonTokens": 16 } };
```

In `module/engine/scheduler.mjs`, wrap the action-table lookup inside `dispatch` before the executor runs:

```js
/**
 * The roll key an action's `chance` is answered by.
 *
 * Named after the action rather than the handler, because one handler may
 * carry several chance-bearing actions and they must not share a roll.
 *
 * @param {object} a the action
 * @returns {string}
 */
function chanceKey(a) {
  return `action:${a.kind}:${a.resource ?? a.ability ?? a.effect?.id ?? "self"}`;
}

/**
 * Whether a chance-bearing action fires this time.
 *
 * The same contract terrain clauses use (`terrainIntents`): the sequence is
 * pure, so the CALLER rolls and the total arrives in `ctx.rolls`. An action
 * whose roll is missing logs itself by name rather than firing or silently
 * vanishing — "the token was not gained" and "the token was never rolled for"
 * are different things, and this codebase keeps losing the difference.
 *
 * Lives in `dispatch` rather than in `ResourceDelta` so that every action in
 * the table gets it; effect RIDERS already have their own `chance` and are a
 * different path (see `ApplyEffect`).
 *
 * @param {object} a
 * @param {SchedulerContext} c
 * @returns {{fires: boolean, missing?: string}}
 */
function chanceVerdict(a, c) {
  if (a.chance === undefined) return { fires: true };
  const key = chanceKey(a);
  const roll = c.rolls?.[key];
  if (typeof roll !== "number") return { fires: false, missing: key };
  return { fires: roll <= a.chance };
}
```

and in `dispatch`, immediately before the executor is called:

```js
const verdict = chanceVerdict(action, ctx);
if (verdict.missing) {
  return [I.log({ kind: "actionRollMissing", action: action.kind, needs: verdict.missing })];
}
if (!verdict.fires) return [];
```

```js
export function boardingTarget(unit, ctx = {}) {
  // A platform that states its own roll states it completely: Drake's
  // *"rolls a ten-sided die… successfully boards if a 10 is rolled"* carries
  // no relief clause, and lending it the Hanging Gardens' would let an
  // AGI-A LUC-A Servant aboard on a 6.
  const authored = ctx.platform?.boarding ?? null;
  if (authored) return { die: authored.die, target: authored.target };

  // "Has the Levitating attribute: roll 1d8 instead, base target 8."
  const levitating = (unit?.attributes ?? []).includes("levitating");
  const die = levitating ? 8 : 12;
  let target = die;

  target -= rankRelief(unit?.parameters?.agi);
  target -= rankRelief(unit?.parameters?.luc);
  if (ctx.hitByDragonWingWarriors) target -= 2;

  return { die, target: Math.max(1, target) };
}
```

**The one number most likely to be wrong and look right.** Riding's MOV Up. Before

sheet says 4. A MOV of 11 instead of 10 is not visibly a bug.

**The stage that matters.** Both Galleon modifiers are **Total** (stage 15). The
sheet says "Total damage dealt" in both directions and §13.4 makes the difference
real. Authoring them at stage 4 changes the numbers and passes every test that
does not check the stage — which is why Task 12's test checks the stage directly.

**The trap in the docs.** §36.3 describes the *previous* version of her Noble
Phantasm. Build from `char_orig_sheets/Copia de Francis Drake.md` and from this
plan's spec, never from that chapter, until Task 14 rewrites it.

**`validate:content` is red from Task 1 to Task 11.** `drake.yml` names eight
refs and they arrive over ten tasks. Do not add stub files to silence it; Task 11
Step 6 is where it must go green.

**The layer rule.** `module/rules/**` may not import from `module/engine/**` or
touch `game`/`ui`/`canvas`. Tasks 8, 10 and 12 all add code to `rules`; keep the
Foundry-facing halves in `engine`.

**Task 12 is three engine capabilities, not one,** and two of them were found
while reviewing this plan rather than while designing it:

  - `totalDamageModifiers` has **one producer** — Cover. No content has ever
    authored a Total Damage modifier, so R5 needed a channel rather than a
    field. If Task 12 feels twice the size of its neighbours, that is why.
  - `damage.sources` resolves against the **board**, and falls back to the
    attacker. Drake's broadside fires with no ship on the board, so the
    fallback would hand back her own 100 and halve the Noble Phantasm — a
    wrong number that looks entirely plausible.

**Two reviewers' traps, stated once more because both are silent failures.**
A `kind: cooldown` phase with `ticks` and no `direction: down` *increases* the
cooldown. A `resource` phase given a bare resource name instead of a path
writes nothing at all.
