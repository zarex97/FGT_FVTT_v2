**Mechanism:** A claim about the code is made from something written about it -- a name (`CASTER_PHASES`), an ADR line ("the client layer does not import in Node"), a glossary entry ("Tick (◈)"), the shape of a call site (a live board at a boundary) -- and built on: a proposal, a plan, a list of bugs. The code said otherwise, and so did a rationale already recorded beside it (`test/helpers/world.mjs`'s header had rejected the very seam proposed). Van Gogh (#239) added reasons written in the code itself: an `fgt-name-ok` marker reasoning a row was shown only to its recipient (the caster reads every row), Terror's file reasoning nothing stood between its 60 and the die (true until #191 moved the die to the landing), and an event described from its name (`damageTaken` read as damage, where it is hit, not hurt). Kiritsugu (#243) added two more: a pipeline comment said *"The NP halving already happened at stage 15"* and no stage read Invuln against an NP, and a test reasoned that the rider gate refused a hit for 0 after §46.4-LI had moved riders to land on a hit. Anastasia (#258) added a grill question that said her own Blind failed 5% of the time: it read the resistance and not the inflict bonus beside it, which cancel, and a test already said 100. The sheet survey (2026-10-21) added two: Saber's Member verdicts given by keyword hid five engine gaps until every group was read, and a regex hit on *"becomes Nightmare"* put Gilgamesh on #294 as a sheet that sets Night. Gilles de Rais (Saber) (#260) added a refusal blamed on a gate from one look at the bar: the card's Counter button had already declared a Normal Attack Counter, and no gate refused the Spell. The survey added four: #284, #287, #290 and #306 named gaps the engine already ran, and a `keys: none` line copied #306's claim instead of running the lookup. Gilles (Caster) (#323) added a grill recommendation built on #293's *"no Turn is the GM's"*: the GM's slot runs every Round.
**Lesson:** Before stating what code does, or proposing a change to it, open the code that does it, or run a probe, and quote it. Read the rationale recorded in the file being changed before proposing to restructure it. A claimed bug names the line that reads the wrong thing, not the shape it was found in. An absence seen once (no toast, no line) is re-pressed watching for it, and the catch that would show it is read (#204). A ticket's "Differs" line is a claim too: three of mine for #218–#223 named defects already built (the Counter against the joint NP, the double count, the Mana Burst Counter), and one did arithmetic the template floors differently. Read the path before writing the line. A comment's or a marker's reason is a claim too: when a fix changes a path, re-read the comments and markers that reasoned about the old one, and read an event's raising line, not its name. A figure in a grill question is a claim: compute it from every term and grep the tests first. A keyword or regex match is a lead: a verdict, or a count of the sheets that carry a rule, comes from reading the Clause. A gap claim ("not run", `keys: none`) comes from `tools/capability.mjs` run on the Clause's words.
