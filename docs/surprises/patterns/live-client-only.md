**Mechanism:** Some defects exist only in a running Foundry client. With no player connected every prompt lands on the GM's client, where two windows with one id are one window. Deleting a Level left the canvas not ready, and nothing redrew it. A player's press is the other half (#206): code that runs on every client, or on the presser's, wrote the Combat from a player who may not, and the unit test drove it as the GM. Yan Qing (#253): four Clauses the board never rolled were filed as unit-tested and the audit ticked; the user refused it.
**Lesson:** Press anything that asks several people at once, or that creates or deletes a Level, on a live board with only the GM connected. Press every player-facing button as Player1 too, and route each write it causes to the active GM (`OPERATIONS`), with the owner as the fallback only when no GM is connected. An audit closes only with every Clause Pressed or Observed live. A case the board did not produce by chance (a duplicate die, a coin's Tails, a large Unit, a survivor) is staged (a dice queue, a staged Unit or stat) and pressed as the player; a unit test never closes a Clause.
