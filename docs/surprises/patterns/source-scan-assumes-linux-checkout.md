**Mechanism:** A test reads source files as text and matches lines and paths. On a Windows checkout every line ends in `\r` and every path uses `\`, so a comment-stripping regex keeps the comment and a path skip never matches: the test fails on the PC and passes on the VPS. A checkout is a shape too: a tool merged in by a pull came out CRLF, and Vite failed to import its `#!/usr/bin/env node\r` shebang (#239).
**Lesson:** Split on `/\r?\n/`, replace `\r\n` before a multi-line regex, and turn `\` into `/` before matching a path. Ch. 44's traps section carries it. `.gitattributes` pins `tools/*.mjs` to LF, which holds it without a habit. A tool that reads authored files is a scan too: content YAML is saved CRLF and LF alike. A fixed character window moves with the line endings: read a function by its bounds (`test/helpers/source.mjs#functionBody`). A script that rewrites a `tools/*.mjs` writes it LF: a text-mode write on Windows puts `` in the shebang.
