**Mechanism:** Code or a test keys on a shape the real data does not have, and the tests agree because they were built from the same assumption. One name meaning two things, `homeBases` for `zones`, a `fixedValue` posing as a Base Attack, a display name compared to an id, "on a platform" meaning "inside a token" when a dimension has none, a hook matching quoted text as if it were a verdict, a board number read as a `{value, max}` pool, a bare snapshot standing in for the board unit, an unlinked token's synthetic actor standing in for the world actor, and one field name (`zon`) holding a Servant's own zone and a Master's stated figure. A `servantClass` read where the board carries `servantClasses`. A definition id used where one instance was meant: a strip of one took every stock. A `nearby` action's `u` read as the bearer when it is each recipient. EMIYA and the Dioscuri added a field id read as the ability's slug, a war setup holding one Servant per slot so the second twin sat with nothing, a test's first reads missing that a 100-point hit is also an Injury Roll, and hand-made test ids of 17 characters where a `DocumentIdField` wants 16. Proto Gil added a ruled property read through a proxy: "single target" asked how many defenders the Processes named, and an area Attack catching one Unit answered yes; the ability's targeting shape is the property.
**Lesson:** Before keying on a name, read one live object of that shape (a board, a log entry, a transcript). Build test data from that live shape, as `test/helpers/subject.mjs` does for authored input. The environment and the library are shapes too: CI checks out part of Foundry, `deepClone` hands a DataModel back as the same object, and a subject's Luck pool is filled only at war setup (Wave B).
