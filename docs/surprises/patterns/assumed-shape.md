**Mechanism:** Code or a test keys on a shape the real data does not have, and the tests agree because they were built from the same assumption. One name meaning two things, `homeBases` for `zones`, a `fixedValue` posing as a Base Attack, a display name compared to an id, "on a platform" meaning "inside a token" when a dimension has none, a hook matching quoted text as if it were a verdict, a board number read as a `{value, max}` pool, a bare snapshot standing in for the board unit, an unlinked token's synthetic actor standing in for the world actor, and one field name (`zon`) holding a Servant's own zone and a Master's stated figure.
**Lesson:** Before keying on a name, read one live object of that shape (a board, a log entry, a transcript). Build test data from that live shape, as `test/helpers/subject.mjs` does for authored input.
