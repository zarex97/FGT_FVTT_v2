# FGT_FVTT_v2

## Agent skills

### Code search

Two graphs, both live: **CodeGraph** (`.codegraph/`) for symbol impact before an edit, **graphify**
(`graphify-out/`) for shape and reach. Consult one before changing a symbol; prefer one over grep to
locate code. Grep stays correct for what a graph does not model — templates, authored content, lang
strings — and for **proving an absence**, which a graph can never do. See `docs/agents/code-search.md`.

### Issue tracker

Issues live as GitHub issues on `zarex97/FGT_FVTT_v2`, managed with the `gh` CLI. See `docs/agents/issue-tracker.md`.

### Triage labels

The five canonical roles, unchanged: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`. See `docs/agents/triage-labels.md`.

### Silent Drops

This project's costliest defect is the **Silent Drop** (`CONTEXT.md`): a Hop on an Authored Key's Route
discards it and nothing fails. When a change adds or moves an Authored Key, a field, or its reader:

1. Declare it on the DataModel. `npm run validate:content` runs the model check and names what else is missing.
2. Give it a route in `test/unit/survival.test.mjs`: projected, or read from the document by a named file.
3. Build test subjects with `test/helpers/subject.mjs` — authored input through the real projection. Data that is not authored follows the same rule: see *Assumed shape* under Lessons.
4. Run tests against real Foundry: `FOUNDRY_PATH`, default `../foundryVTT_copy`. A missing copy fails.
5. Prove "unread" or "never written" with grep; `test/unit/field-ledger.test.mjs` does it for every field.

The map of Hops is in `docs/07-schemas.md`, the guards in `docs/44-testing.md`, the reason in ADR-0006.

### Surprises

When the board, a test or the user contradicts what the design or I expected, record it with the
`record-surprise` skill before the turn ends. `/review-surprises` fuses them into patterns and the
lessons below. The records live in `docs/surprises/`.

### Lessons

One line per pattern `/review-surprises` confirmed, each linking its file in `docs/surprises/patterns/`.

- **Producer without consumer.** "Built" means everything a feature emits has a consumer: grep for the reader of each hook, key, option and record before calling it done, and give every outcome (resisted, ended, deferred) a line a player sees, naming who and the real change, read on screen as a player would. A log entry is not a line: an outcome a player must know needs a card. A form field is built only once a test reads it back off the document it saved. A reader whose answer is never applied is no reader. A die that decides an outcome is on the card, and so is an attempt that fails. A flag a stage raises has a writer that acts on it, and every removal, done or held, is a line. A refusal names what it waits on. A field that is read has a writer. A record a run writes is read before it writes again, and a pool that is spent is refilled at every boundary that opens it. A batch goes through the door that puts its lines on the card, and a key built from a value has a guard over every value. A clause its gate holds back is a line, and a card prints the reason a Process holds, never a generic label. A press reads each outcome off the card, never the sheet. A figure a sheet shows has a reader in the action it governs. An area a player must see is drawn for players. A field that is written has a reader where it governs. A handler's every write is said, the pools beside Health too. A card says only what a write made: every path that announces a change makes it. A card row says whose it is. A window that waits on a person offers a way to pass. Every placeholder in a string has a writer. A card names an effect by its name, never its id. A card's close names what ended, never a neighbour's fall. A Turn's start says what its handlers did, as its end does. An effect that ends says what it takes. A negation names what it removed. Two writes to one clock are one line. [pattern](docs/surprises/patterns/producer-without-consumer.md)
- **Two readers, one rule.** When adding or fixing a rule, find every other place that answers the same question and make them call one reader. The preview, the bar and the card are readers too, and so is every door the engine opens on a Unit's behalf (a periodic tick among them), and every option set a predicate is tested against, wherever it is built. An offer is a reader of the use gate: a window, a rung or a prompt offers only what its press would pass. A Unit named on a line or a prompt is `publicIdentityOf`'s, and a Unit's document is `unitActor`'s, never `game.actors.get`'s (a summon's token is unlinked). A derived state (Unbound, Free, Grand Order) is asked of its deriver, never of a stored word or a context that may lack it. Foundry's own guess is a reader too: the War is `currentWar()`'s, never `game.combat`'s, `game.combats.active`'s or the tracker's. A rule added after a shared step belongs in that step, where every reader passes, and a prompt is a reader of the card it precedes. A boundary handed a War reads that War's things only. A War Rule is `warRule`'s, never the world setting's; a list is the War's board, never the canvas's; a floor holds on every path to 0, an Instakill's too. When a lesson lands, sweep the old sites too. A fact one stage derives reaches every reader before it too; a mirror event rolls its twin's dice; a card's verdict is the landing's own; a rule an effect authors is never hand-written again in the engine. Two writers of one state write one patch. A rule about a kind of effect asks its family, never one id; a seat is not a Class. Who a compulsion names is who its Attack may target. A tool's GM page is `foundryTarget`'s. An ability a line names is its name on every path that says it, the engine's refusals too. A step that replaces a Process's defender records whom it replaced. A wait for a reply reads the windows it waits on. A rule about every holder walks the documents, the defeated too, never the board alone; a token placed at a Unit's feet sinks beneath it, as a platform does. A list a gate filters asks the gate whether the item is held yet. A sync of a derived value hears every write to its inputs, an item switch too. A report reads its batch after the door that changes it. A new action asks the gate its kind of action asks: an escape in place of a Move asks what stops a Move. A swing is heard by the mount and its rider alike. A window a press names is asked by its spend, not the bar alone: an own-Turn Command Spell is the Master's own Turn. [pattern](docs/surprises/patterns/two-readers-one-rule.md)
- **Assumed shape.** Before keying on a name or shape, read one live object of it, and build test data from that live shape. The environment a test runs in and what a library call returns are shapes too, and so is what a flag stores and an update writes back. A library option does only what its source says: read Foundry's code before relying on one. A test subject is roster content as authored, its own skills read first, never one with a field written in; a content key does what its executor says. A file's line endings are a shape too: split on `\r?\n`, read them with Python or `file`, never Git Bash's `grep`/`cat`, and write the file's own ending. An area is the attack's declared panels, never the panels its defenders stand on. A unit is a shape: sum in the sheet's unit, convert once. A Unit is its footprint, never its anchor: distance, path and reach are footprint to footprint (`occupiedPanels`). [pattern](docs/surprises/patterns/assumed-shape.md)
- **A sheet binds only its owner.** A Servant's sheet governs its bearer: another Unit's side is that Unit's own sheet, and a condition or a figure one sheet states ("weak to", "while inside", a count, a Rank, a title) lives on the element that sheet authors, never in the reader others share. A phrase on one bearer's copy of a shared Skill is that bearer's own: read the shared text from a sheet that prints it plainly. [pattern](docs/surprises/patterns/sheet-binds-only-its-owner.md)
- **Role keyed on type.** When code asks about a role (Master, summoner, owner, guard), ask about the relationship that confers it, the contract, never the actor's type, its side, the player who holds it or what it carries; a role is held in this war, on this board. A role's fields are declared on every document type that can hold it. A role ends with its contract: ask whether it holds when asked. A rule that outlives a role records its holder when it starts. [pattern](docs/surprises/patterns/role-keyed-on-type.md)
- **Hidden timing rule.** For every "first", "then", "if defeated" or "when X" clause, find the key that sets its timing and press the order live. A boundary reads the cycle that ended, not the live clock. For each event, ask who hears it and what already exists when it fires. An irreversible step waits for the last gate, and a "while X" reads X at declaration. A control for a setting exists while the setting can still change, and anything that waits on a person writes what it shows first, then waits. A clock or a mark is keyed as finely as what it times: a prompt, not its card; an order within a Turn, not the Turn. A predicate on a board annotation is asked after the board is built, never at collection. A span is read at every Turn of it, not at its end; a line is said before what it brings runs. A cost is paid before what it powers. A charge spent by "the next" use is spent only by a use begun while it was held. A gate asked after writes in the same pass reads the live document, not the pass's board. A write capped by a ceiling lands after what raises it. A wait that stops waiting takes back what it showed. A step after the hit is asked what a miss does. A payment that can fell its payer asks the defeat again after it. A move made beside a teardown goes through the teardown. [pattern](docs/surprises/patterns/hidden-timing-rule.md)
- **Generic path escapes the special case.** When a sheet bends a generic mechanic, list every exit the generic path offers (edges, toggles, prompts, buttons, revivals) and every exit's way back, and close each one the sheet rules out, in the engine and not only on the bar, best at the one door every path passes. [pattern](docs/surprises/patterns/generic-path-escapes-special-case.md)
- **Write before store.** A run that writes and then waits stores how far it got right after the write, and a stored state that waits on nobody has a driver on load: a run lives in one client's memory. A field the engine writes in play is seeded, then the world's (`SEEDED_THEN_OWNED`), or the next load reverts it. [pattern](docs/surprises/patterns/write-before-store.md)
- **Check-then-act race.** When several async flows can reach one decision together (a fan-out's Processes, a hook burst), claim it in memory and make the rest await the claim; never decide from a record a sibling writes later. [pattern](docs/surprises/patterns/check-then-act-race.md)
- **Claim without reading.** A doc line, a glossary entry, a name or one look at the screen is not evidence: read the code, or probe it, before telling the user what it does or proposing to change it, and read the rationale already recorded in the file you would restructure. A ticket's line is a claim too: read the path before writing it. So is a comment's or a safety marker's reason: when a fix changes a path, re-read what reasoned about the old one. A figure or a reading in a grill pick is a claim: compute it from every term, and grep the term's rulings and tests first. A keyword or regex match is a lead: a verdict or a sheet count comes from the Clause read. A gap claim ("not run", `keys: none`) from `tools/capability.mjs` is a lead: confirm the key in the code before calling it missing. Read the definition of each effect a clause names before a grill pick. Read what the core rules already pay before a sheet adds a payout. A grill pick names the defaults it touches (a War Rule's initial value) and quotes the reader that runs the rule, never only the text that describes it. [pattern](docs/surprises/patterns/claim-without-reading-the-path.md)
- **Passes for the wrong reason.** A check asserts the reason it fails, not only that it failed; when the test world takes over something a test stubbed, the test fails out loud instead of passing on the new default. A test that hands a function what its caller supplies proves nothing about that caller. When a guard's count falls after a rename, widen its pattern and never lower the count. A test names the War Rules it relies on. A source scan matches a named marker, never a whole line or a fixed slice. Before changing a call's text, grep `test/` for it. [pattern](docs/surprises/patterns/passes-for-the-wrong-reason.md) [scan](docs/surprises/patterns/source-scan-pins-text.md)
- **Unknown value falls to default.** When content gains a value, find the executor's switch and its default branch: an unknown value refuses out loud, and the guard walks every nesting where it can sit and every source of the values. The build checks every closed word a resolver reads. A null is a value with its own branch: no ability is a Normal Attack. A refusal costs its own clause, never the board. [pattern](docs/surprises/patterns/unknown-value-falls-to-default.md)
- **Qualifier quoted, not checked.** Every qualifier a quoted clause names ("enemy", "within Range", "allied") has its own guard: point at the line that checks each one, and test the case it excludes. Scope words count: "every Unit", "when it Attacks"; test the case each excludes, an ally or a Skill. A parenthetical is a qualifier: "no effect if no damage is dealt". [pattern](docs/surprises/patterns/qualifier-quoted-not-checked.md)
- **Press as a player.** Press every player-facing button as Player1, not only as the GM; every write a press makes runs on the active GM, the owner only when no GM is connected. Every Clause ends Pressed or Observed live: a case the board does not produce by chance is staged and pressed, never left to a test. A shared file's Clause is pressed on the Servant under audit; a tracker is ticked only then. [pattern](docs/surprises/patterns/live-client-only.md)
- **Rule word read one way.** When a sheet phrase can be read two ways, grep the same document's other uses of the term, then put both readings to the user before building; a list two rules share is a reading too, and so is an event's name, read against the clause that listens to it. A value the sheet leaves out is a reading too, never a guess; so is one sheet's clause meeting another's, and a mark the sheet prints. A reading carried from another audit goes to the user with its source and its scope. [pattern](docs/surprises/patterns/rule-word-read-one-way.md)
- **Declaration or Process.** An area attack is one declaration and many Processes: before placing an effect, ask which one it names (the attack, its user, the NP: the declaration's, paid once and carried to every Process; the defender or the hit: the Process's), and press it on two targets. [pattern](docs/surprises/patterns/declaration-or-process.md)
- **Sources stay in the repo.** Rules come from the repo's docs, sheets and issues; a connector being there is not leave to search it, so name the missing source and ask for it. A sheet copied into the repo is a snapshot: compare it with its source before building. [pattern](docs/surprises/patterns/source-outside-the-repo.md)
- **Guards span the suite.** Before a commit, run the full suite at four workers, lint and `validate:content`, and change the docs chapter the work touches: a new piece is guarded by tests far from its own file. [pattern](docs/surprises/patterns/guards-span-the-suite.md)
- **Shared working copy.** Work in the main checkout on a branch, so Foundry runs what you build; no worktree. Before blaming a red test or committing, run `git status` and name the files that are not yours. [pattern](docs/surprises/patterns/shared-working-copy.md)
